# Experimental NPC information events

Enable **World Info · entity reference → Track NPC information events (experimental)** to prepare a source-linked journal of who observed something or received a statement. The default is off. **Include related source evidence (local graph, experimental)** is a separate optional setting, also off. A general gameplay benefit of the graph has not been established.

The first background request saves L0 and its story outline as before. The existing second request prepares search notes, WI and the enabled information-event field together. A received report is not automatically true or believed; an actor missing from the journal is not automatically ignorant. Later original dialogue can establish new discovery. The narrator keeps access to the whole story and its secrets.

Events carry the provided managed character references, a precise topic, an exact quotation and its source link. Code binds them to original ranges/revisions and a persisted character instance. Source edits, hidden or unavailable sources, changed L0 and reused character UIDs can invalidate derived events. Exact quotation validates provenance, not the model's interpretation. Original and manual WI content is preserved. Previously stored experimental epistemic rows remain available as legacy data; new preparation requests events.

During Chat Completion generation, native WI chooses character profiles using its normal keyword, Constant, group, probability and budget rules. The addon applies native WI regex/depth rules, then prepares separate, non-scannable GM context for eligible managed profiles. A final prompt check can withhold the optional context when a selected profile is absent. Presence is checked by rendered text, not a native UID trace through every third-party prompt transformation.

The optional local graph links the same events to actors, source messages and exactly matching topics. It can add a bounded amount of related evidence. Acquaintance does not transfer knowledge. No graph database, extra embedding model or generation request per RP turn is required.

The added GM context participates in native prompt budgeting. It has a 12,000-character cap and keeps whole event rows. If the combined graph view exceeds that cap, it falls back to direct events and keeps recent whole rows in source order. This is a character cap, not a guaranteed token allowance or a reduction of the saved archive. The complete story outline and normal history retrieval are unchanged.

Existing L0 packets need an explicit **Rebuild search notes / WI** or **Prepare missing search notes / WI** operation; this can make a second-stage model request for each selected packet. Only already managed character identities are eligible. If that request first creates the profiles, event preparation for those characters may require a later pass. Unsupported or missing event output does not erase saved L0 or valid search/WI data. An empty event array is valid.

Information-event injection currently requires **Chat Completion**. Other API modes retain stored events without adding this experimental context. The conventional Chat Completion backend's authorization settings, phone performance and every WI filtering mode have not been qualified by this feature's limited acceptance run. Inspect `WorldMemory.inspectKnowledge()` when diagnosing preparation, selected profiles and delivery.
