# 0.5.2: measured scope

## Context controls and automatic compression

The desired context C is a planning reference. Protected exchanges P are outside it. Manual history, tail, trigger and WI values remain independent: editing C does not silently rebalance them. The recommendation button is explicit; the planner reports the resulting total, difference from C, the full outline, retrieved details and free history space. Card/system/hint overhead uses a labelled planning reserve until measured; a stored assembled-prompt total is displayed separately.

**24 existing and new automated checks passed.** Four new cases verify that recommendations include trigger headroom, 22k of older eligible raw text can trigger before a 24k source packet is full, the complete outline survives a small history allowance, and manual 24k tail settings remain unchanged when C changes. The threshold case also exercises the production raw planner with protected exchanges. No new model request is required for these checks.

A native ST panel at 390px verified: manual R24k/H12k/T4k/W4k/F4k gives a planned 48k at C32k; changing C to 24k preserves all those allowances. A manually changed native WI cap remains in effect after changing C. Removing the absolute WI cap disables the numeric control and labels the estimate as unbounded; ST's native percentage budget and entry rules still apply. Applying recommendations explicitly restores the selected recommendation. The saved archive remains unchanged; no model/external requests or page errors occurred. A desktop browser at mobile width is not a physical-phone test.

Automatic preparation now uses T, not the maximum source-packet size B, as its readiness threshold. Whole-message boundaries and retention can exceed a planning value. Original chat, protected exchanges and complete outline are not clipped to make a target appear successful.

## One-image transfer

Native PNG import on a fresh ST data directory automatically restored **228 messages, 52 saved packets/outlines and 13 author-WI entries** from one image. The author book was initially absent; a separate native chat book was created and linked. Original text, IDs, packet membership, outlines and saved source records remained intact. ST added its normal default swipe fields to some assistant messages. Reload and native PNG export preserved the embedded game without separate chat or backup-file imports.

This path made **0 model/external requests**, with no page errors. The fresh profile used the new embedding/hint defaults. Concurrent chat-switch guards received clean code review; the ordinary transfer run is not a separate race reproduction. Physical-phone qualification remains deferred.

## Embedding and optional-feature selection

Cached `gemini-embedding-001` / 768 and `gemini-embedding-2-preview` / 768 were compared on **240 assemblies / 120 pairs** using the same complete outline, original sources, player posts and question triples. No new embedding/generation requests were made. At the nominal 32k envelope, fully supported needs on natural posts increased **33 → 37**, with four support improvements and no support losses; question triples also included individual losses. Across all needs, full/partial/unconfirmed changed **93/8/37 → 99/10/29**.

All outlines and chronological source placement survived. All assemblies crossed their soft envelope by a whole-window increment, maximum **1,233 reference tokens**. These are retrieval-support observations on previously inspected corpora, not a blind RP win rate, a hard-fit qualification or a claim about the stable Embedding 2 model. Hints remain an engineering default without a controlled on/off result. Other optional additions remain off because their combined gameplay benefit was not established.
